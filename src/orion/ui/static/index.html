1. System Overview & Autonomous Architecture

ORION is an industrial-grade Autonomous AI Software Engineering Operating System. Rather than treating code repair as an open-ended conversational prompt, ORION models engineering work as a deterministic directed acyclic graph (DAG) across verified repository states.

All mutations occur inside strict workspace boundaries, pass through syntax validation, are locked by cryptographic hashes, require dual-key human approval where configured, and must be certified by an independent VerificationEngine authority before being marked complete.

2. The Deterministic 7-Stage Engineering Graph

Every engineering mission follows a strictly sequenced state machine:

  • Stage 1 (INSPECT_REPOSITORY): Workspace boundary check, AST parsing, symbol indexation, and test target discovery.
  • Stage 2 (ANALYZE_FAILURE): Root-cause taxonomy classifier, traceback isolation, blast radius calculation.
  • Stage 3 (FORMULATE_FIX): Context-bounded patch synthesis, unified diff formulation, and AST syntax validation.
  • Stage 4 (APPROVAL_GATE): Dual-key human approval check. Verifies single-use cryptographically signed approval token.
  • Stage 5 (IMPLEMENT_CHANGE): Controlled file application with SHA-256 hash concurrency verification.
  • Stage 6 (RUN_TESTS): Bounded sandboxed pytest runner execution (subprocess with shell=False).
  • Stage 7 (VERIFY & REPORT): VerificationEngine evaluates ground-truth acceptance criteria and produces cryptographic certified report.

3. Agent Workforce & Role Policies

The ORION workforce comprises four distinct autonomous specialists with least-privilege tool policies:

  • SWE Specialist: Handles code transformations and patch generation within write boundaries.
  • Diagnostics Agent: Analyzes AST code structures, symbol references, and error taxonomies.
  • Verifier Agent: Authority responsible for independent verification and test evaluation.
  • Recovery Coordinator: Manages self-healing bounded recovery loops (capped at 3 attempts, 120s runtime).

4. The 20 Non-Negotiable Security Invariants

ORION enforces 20 formal security invariants:

  • Frontend is untrusted; model output is untrusted; repository contents are untrusted.
  • Arbitrary shell execution is forbidden; shell=False is enforced for all subprocesses.
  • Workspace containment is mandatory; symlink, UNC, and path traversal escapes are rejected.
  • Protected files (.git, .env, secrets) are immutable and cannot be modified.
  • Approval tokens are single-use; replay attacks are cryptographically rejected.
  • Zero fake telemetry; all SSE streams and status indicators mirror live internal state.

Privacy Policy

ORION Platform • Effective Date: October 2026 • Strict Local-Execution Policy

1. Local Processing Guarantee

ORION is built as a local, self-contained autonomous software engineering system. All AST analysis, repository file reading, patch synthesis, subprocess test executions, and verification processes occur 100% locally on your designated host machine or private container. No repository code or AST graphs are transmitted to third-party tracking services.

2. Telemetry and Analytics Policy

ORION contains zero third-party telemetry libraries, tracking beacons, advertising cookies, or behavioral analytics. All health probes, metrics, and event streams (SSE) are served strictly over the local HTTP server interface for the sole benefit of the operator.

3. Automatic Credential & Secret Redaction

Under Security Invariant 12 and Invariant 18, all hardcoded API keys, OAuth tokens, private SSH keys, and contents of protected files (.env, .git) are automatically scrubbed and redacted before any data enters distributed trace spans, unified diffs, or forensic evidence ledgers.

4. Workspace Containment & Isolation

Under Security Invariant 6, all filesystem operations are strictly bound to the canonical root of the workspace designated at mission initialization. Path traversal attempts, symlink escapes, UNC paths, and directory boundary breakouts are rejected with immediate failure.

Autonomous code generation involves modifying source repositories. In Controlled Execution Mode, ORION requires explicit human authorization through the dual-key approval gate before applying any patch to disk. 3. Non-Destructive Simulation & Rollback Guarantee

ORION's Self-Healing Recovery Coordinator executes patches with transactional hash locks and non-destructive simulations.
